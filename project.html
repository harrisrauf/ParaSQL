Parquet Viewer v0.2.0

A native desktop Parquet file management application powered by DuckDB. Opens, views, edits, and saves Apache Parquet files with full SQL support, all Parquet types, virtual scrolling for performance, and a modern Svelte 5 UI. Built with Tauri v2 (Rust backend) + DuckDB (embedded database) + Svelte 5 (frontend).

1. Project Idea & Philosophy

What this project is and why it exists

Purpose

Apache Parquet is the dominant columnar storage format in the data engineering ecosystem. This project provides a native desktop application for interacting with Parquet files — not just viewing data, but querying, editing, and managing it with the full power of SQL. Powered by DuckDB (the same embedded OLAP database used by DBeaver, dbt, and modern data tools), it handles all Parquet types including nested structures (List, Map, Struct), and provides a CodeMirror-powered SQL editor for ad-hoc queries.

Core Principles

  • DuckDB as the data engine — DuckDB is an embedded OLAP database that natively reads Parquet files, executes full SQL, and outputs Arrow record batches. It provides buttery-smooth performance for queries, filtering, sorting, and pagination across datasets of any size.
  • Full Parquet type support — DuckDB handles all Parquet types natively: INT32/64, FLOAT/DOUBLE, BOOLEAN, STRING, DATE, TIMESTAMP, DECIMAL, UUID, BINARY, LIST, MAP, and STRUCT. The arrow_array_to_json function converts Arrow batches to JSON for the frontend, with recursive handling for nested types.
  • SQL-first approach — Users can write SQL queries directly against loaded Parquet files via a built-in CodeMirror 6 editor with syntax highlighting and autocomplete. This makes the app a lightweight Parquet-native database client.
  • Virtual scrolling — The DataTable uses TanStack Svelte Virtual to render only visible rows (~30 at a time), providing buttery-smooth scrolling regardless of dataset size.
  • Incremental patches — Mutations return only changed rows, not full snapshots. The frontend patches its store incrementally.
  • JSON for IPC — All IPC between Rust and the frontend uses JSON serialization for simplicity.
  • Dark mode — CSS custom properties with localStorage persistence. Toggle via toolbar button.

IPC Data Flow

  1. Open File: Frontend calls Tauri dialog → sends path to open_file → DuckDB loads Parquet via read_parquet() into in-memory table with _row_id → returns MetadataJson. Frontend calls get_all_rows to fetch data.
  2. SQL Query: User types SQL in CodeMirror editor → sends to execute_sql → DuckDB executes query → Arrow RecordBatch converted to JSON → returns QueryResult with columns and rows.
  3. Mutation: Frontend sends edit_cell(row_id, col_idx, value) → DuckDB executes UPDATE working SET col = value WHERE _row_id = id → returns updated row as QueryResult.
  4. Save: Frontend sends save_file() → DuckDB executes COPY working TO 'file.json' (or CSV). For Parquet save, uses DuckDB's Parquet export.

Row Identity Model

  • DuckDB creates _row_id as row_number() OVER () when loading the table — stable auto-incrementing u64.
  • All mutations reference rows by _row_id, not by view index.
  • Sorting and filtering use SQL ORDER BY / WHERE clauses — the _row_id remains stable.

Unsaved-Changes Guard

App.svelte uses getCurrentWindow().onCloseRequested() to intercept window close. If the store's modified flag is true, it shows a native confirm dialog ("You have unsaved changes. Close anyway?"). The close event is prevented if the user cancels.

OpLog Implementation

struct OpLog {
    entries: Vec<OpEntry>,     // operation history
    position: usize,            // current position (pointing to next to undo)
    max_entries: usize,         // default 500
}
  • push(entry) — Truncates redo entries (entries.truncate(position)), pushes new entry, evicts oldest if over max_entries, sets position to end.
  • undo() → Option<&OpEntry> — Decrements position, returns entry at new position.
  • redo() → Option<&OpEntry> — Returns entry at current position, increments position.
  • can_undo() / can_redo() — Check position bounds (used by frontend for button states, wired but not currently called).

6. Rust Backend — Parquet I/O

parquet_io.rs — read_parquet and write_parquet

src-tauri/src/engine/parquet_io.rs (96 lines)

read_parquet(path: &Path) → Result<(RecordBatch, FileMetadata), String>

  1. Opens file with File::open.
  2. Creates ParquetRecordBatchReaderBuilder from file handle.
  3. Extracts file_metadata from builder metadata (used later for original file info).
  4. Sets compression to Compression::SNAPPY (default — original writer_props() API removed in Parquet 54).
  5. Gets row group size from metadata.num_rows().
  6. Builds reader and iterates over all batches.
  7. Multi-batch concatenation: If the file has multiple batches (common in large files), concatenates column-by-column using arrow::compute::concat.
  8. Returns (combined_batch, file_metadata) or error for empty files.

write_parquet(path, batch, file_meta) → Result<(), String>

  1. Builds WriterProperties from file metadata (compression codec, data page size).
  2. Creates ArrowWriter with the schema and properties.
  3. Writes the single batch.
  4. Closes the writer (flushes footer).

Key detail: On "Save As" (no file_meta), uses FileMetadata::default() which sets Snappy compression, row group size 1024, data page size 1MB.

Arrow 54 Compatibility Notes

  • Fields API: Schema's fields() returns &Fields, which wraps Vec<Arc<Field>> with no push/remove. Solution: iterate with .map(|f| f.as_ref().clone()) to get Vec<Field>, modify freely, then Schema::new(fields).
  • Slice lifetimes: RecordBatch::slice() returns a batch that borrows from parent. Column references from sliced batches must be cloned into Arc<dyn Array> before passing to concat().
  • Non-nullable insert: RecordBatch::try_new validates non-null constraints. Inserting a row with nulls into non-nullable columns fails. Solution: append_default for non-nullable fields.

displayedRows — Derived Store

export const displayedRows = derived(tableStore, ...) — Computes the filtered + sorted row view for rendering:

  1. Search filter: If search.query is set, filters rows to those where any cell's string representation contains the query (case-insensitive). If search.column is specified, only searches that column.
  2. Sort: If sort.direction is non-null, sorts rows by the specified column. Nulls sort last. Numbers sort numerically, everything else sorts as case-insensitive strings.

Important: This is a derived store (computed, not cached). It re-computes whenever $tableStore changes. The original $tableStore.rows is never mutated — only the derived view changes.

14. Future Scaling & Upgrades

Ideas discussed but not yet implemented for v0

Performance & Scale

FeatureDescriptionWhy deferred
Virtual scrolling Replace naive {#each} rendering with windowed rendering (e.g., TanStack Table or custom virtualizer). Only render rows in the visible viewport + buffer zone. v0 targets ≤30MB files (~tens of thousands of rows), which renders fine without virtualization. Beyond that, DOM nodes become a bottleneck.
Pagination / Lazy loading For files >30MB, load data page-by-page via get_data_slice(start, end) Tauri command. Show page controls in the status bar. v0 assumes full in-memory load. Pagination adds complexity to both Rust (offset-based batch slicing) and frontend (page-aware store).
Arrow IPC binary for IPC Replace JSON serialization with Arrow IPC binary format (the native Arrow wire format). This preserves int64, Decimal128, timestamps, and large lists without precision loss. v0 uses JSON for simplicity. Arrow IPC binary requires @apache-arrow JS bindings on the frontend and Tauri's asset protocol for binary streaming. The original design spec assumed this, but JSON was simpler for the initial implementation.

New Features

FeatureDescriptionImplementation approach
SQL query mode Pass-through SQL queries executed by DataFusion on the Rust side. Users type SQL, results render as a new table view. Add datafusion crate dependency. Create a SqlEngine that wraps DataFusion's SessionContext. Register the loaded RecordBatch as a table. Tauri command: execute_sql(sql: String) → MutationResult or full result set.
Export Export the current data to CSV, JSON, or SQLite files via Tauri save dialog. New export_ commands in Rust using csv crate, serde_json for JSON lines, or rusqlite for SQLite. Frontend gets an Export menu item.
Column statistics Show min, max, null count, distinct count per column — either in the SchemaPanel or in a tooltip/popover. New Tauri command get_column_stats() that computes stats using Arrow compute kernels (min, max, null_count, distinct). Frontend shows next to column name.
Bulk edit / Multi-cell paste Select multiple cells → paste from clipboard or apply a formula-like transformation (e.g., "column = column * 2"). New bulk_edit command accepting a map of (row_id, col_idx) → value. Clipboard integration via Tauri's clipboard plugin.
Side-by-side diff Open two Parquet files and highlight differences between them. Second Engine instance. Row-by-row comparison based on _row_id. Highlight changed/inserted/deleted cells.
Nested type support STRUCT columns show as expandable sub-headers. LIST/MAP columns show JSON preview — click to open NestedValueModal with syntax-highlighted view. Implement arrow_array_to_json handling for StructArray, ListArray, MapArray. Component NestedValueModal.svelte with collapsible tree view.

FeatureDescription
Undo/Redo button states Wire can_undo/can_redo methods to disable toolbar buttons when no history exists. Requires a frontend call to get_file_info or a dedicated can_undo command, or tracking undo stack size in the store.
Keyboard navigation Arrow keys to move between cells, Tab to move to next cell, Enter to edit. This requires focus management across table cells and a "focused cell" state in addition to "editing cell".
Broader type coverage Display and edit support for DATE, TIMESTAMP (millis/nanos), DECIMAL, FIXED_SIZE_BINARY. Each needs type-specific formatting, input controls, and arrow_array_to_json handling.

Error toast notifications Replace console.error with in-app toast notifications for mutation failures.
